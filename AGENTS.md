# Правила для агентов

- Это мобильная 2D-раскраска по номерам. Не ломайте существующие уровни и переходы между сценами.
- **Для новых изображений действует строгий однотонный стандарт**: 1254×1254, 12–45 логических RGB (цель 20–45), замкнутые зоны; один `Zone_XXX.png` на один RGB со всеми островками, без градиентов внутри игровых PNG. Перед новым импортом выполняется `Tools/LevelCreation/check_flat_source.py`. Старые уровни и явный legacy-`layer` режим сохраняют исходную графику; подробности в [LEVEL_PIPELINE](docs/LEVEL_PIPELINE.md).
- Технический эталон — `Assets/_Project/Scenes/Level_002_New.unity`. Актуальные включённые сцены читайте из Build Settings; не подменяйте New-уровни отключёнными legacy-сценами.
- Перед любыми изменениями выполняйте `git status --short --branch`. Не перезаписывайте и не откатывайте чужие незавершённые изменения.
- Не меняйте сцены и ассеты вне текущей задачи. Не удаляйте, не перемещайте и не переименовывайте ассеты или `.meta`-файлы без явного указания пользователя.
- Работайте через открытый Unity Editor и подключённый Unity CLI/MCP; сначала используйте проверки только для чтения. Не запускайте второй Editor для того же проекта.
- После изменений кода/ассетов дождитесь импорта и компиляции, проверьте новые ошибки Console. Для игровой логики выполните затронутые сценарии на обычном и сложном уровне; общий runtime требует целевых регрессий остальных включённых уровней. Перед игровыми тестами сохраните пользовательский прогресс, после тестов восстановите.
- APK собирайте только по заданию пользователя; запрос только на сборку не требует повторного полного аудита или игровых прогонов неизменённого кода. Успех сборки подтверждайте BuildReport и созданным APK. Play Mode и синтетический touch не заменяют проверку на Android-устройстве.
- Не обновляйте версию Unity или пакеты проекта без необходимости текущей задачи. При новых ошибках остановитесь, сохраните точный текст ошибки и сообщите пользователю.

## Короткий вход в проект

После этого файла используйте `Tools/Get-AgentContext.ps1 -Compact`, затем **только нужный** раздел [индекса](docs/INDEX.md). Полный аудит, STATE и inventory по умолчанию не повторяйте.
Текущее состояние диска определяют Git и Editor. `AgentSync/STATE.json` — датированный снимок с HEAD, хешами и границами проверок; STATUS и STATE_LITE — его представления. Исторический PASS не считать проверкой изменённого кода.

Механика: выбрать цвет, затем применить его к одному участку — раскрашиваются все участки этого цвета.
В текущих уровнях один `PaintZone` содержит полный PNG цветовой группы с раздельными островками.
Не создавайте несколько PaintZone с одним colorId без проверки GAMEPLAY_SYSTEMS.
Числовые TMP-подписи намеренно скрываются существующим кодом; не включайте их без согласования.
Основные runtime-скрипты — `Assets/_Project/Scripts/`, общий WinPanel — `Assets/_Project/UI/WinPanel/`.

## Завершение задачи

- Обновляйте только документацию, чьё описанное поведение изменилось. При изменении ссылок выполните проверку docs; inventory обновляйте при изменении состава/связей ресурсов, а не после каждой мелкой задачи.
- Обычно достаточно краткого ответа: изменения, проверки и ограничения. AgentSync формируйте/публикуйте при явном запросе или необходимой передаче состояния между чатами, один раз после завершения работы по [AGENT_SYNC_GUIDE](docs/AGENT_SYNC_GUIDE.md). Передавайте только проверенный текст; корневой STATE обновляется последним после readback снимка.
- Не включайте Editor.log, дампы окружения, пароли, токены, весь проект или PNG в обмен. При обнаружении секрета остановите публикацию.
- Не делайте commit/push без отдельной команды. Отчёт локальных изменений не является публикацией в GitHub.
- Явная остановка проверки пользователем имеет приоритет: фиксируйте `not_run`/`stopped_by_user`, не возобновляйте APK автоматически.

Контракт изображений, подготовки и готовых комплектов — [LEVEL_PIPELINE](docs/LEVEL_PIPELINE.md). MANUAL_REVIEW не разрешает импорт. Palette suite требует разрешённого игрового прогона и не является полной регрессией жестов/сохранений.
