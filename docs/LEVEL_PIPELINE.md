# Создание уровней «Умной раскраски»

## Действующий стандарт новых иллюстраций (30.10.2026)

**Обязательные видимые линии:** все игровые цветовые области имеют замкнутый тонкий тёмный контур; **каждая смена RGB отделена линией**, включая тени, листья, небо, траву и шерсть. Не допускаются цветовые пятна без разделительного контура. Раскраска использует неизменную геометрию утверждённого чёрно-белого мастера; при потребности в новой области сначала согласовывают исправление B/W-контура. При выводе спрайтов `outlines.png` всегда поверх `Zone_XXX.png`. Прямое соприкосновение двух разных игровых групп без непрозрачного разделительного пикселя считается ошибкой `BLOCKED`, даже если палитра однотонная. Проверка по соседним пикселям не доказывает полную замкнутость каждой линии или художественную сохранность оригинала: обязательна визуальная оценка наложения цветной версии и B/W-контура.

**Видимый порядок работы для новых рисунков:** просьба «нарисуй», «сделай картинку», «создай раскраску» без прямого указания цвета сначала возвращает пользователю **только чёрно-белый мастер** с замкнутыми контурами. Нельзя скрыть этап контура и первым результатом показать цветную картинку. Пользователь может править контур; после утверждения/прямой команды «Раскрась» создаётся однотонная цветная версия по той же геометрии. Далее после утверждения цвета — экспорт для Unity. Исключение — явно заказанная сразу цветная картинка или полный автономный цикл. Запрос на новый рисунок сам по себе не разрешает пропускать показ контура.

### Фиксация геометрии и контролируемая окраска (Smart Coloring Pipeline 0.4.0)

1. Покажи пользователю только чёрно-белый контур и дождись утверждения. Повторно генерировать цветную версию изображением **запрещено**: это меняет геометрию.
2. Плагин делает `python scripts/locked_region_pipeline.py extract --ink Approved_BW.png --out NewOutput`. Полное игровое полотно 1254×1254. Результат: исходный B/W побайтно, `Review/Region_ID_Map.png`, `Review/Map_Numbers.png`, `Review/regions.json`, обязательный черновой `region_review.json` и `color_plan.json` с `approved=false`.
3. При наличии цветного референса допускается `--reference ColorReference.png --suggest 28` для **только черновых** RGB-подсказок. Геометрия всегда из B/W. Художественное назначение ID проверяется вручную; когда линия не замкнута, она может слить соседние области, и это требует исправления B/W до нового extract.
4. **До раскрашивания:** показать `Map_Numbers.png`, проверить художественное назначение каждой замкнутой зоны, наличие задуманных деталей (например, светлая мордочка, грудка, внутреннее ухо или птичье оперение). В `region_review.json` каждому ID присвоить осмысленный `approved_role` и `reviewed=true`. Отсутствующая отдельная граница → `needs_split=true` / `needs_merge=true`, объяснение, статус `CONTOUR_INCOMPLETE`; исправить B/W и повторно извлечь регионы. В `required_details` записать важные для конкретной композиции детали и их `region_ids` с `verified=true`. После проверки и **явного подтверждения пользователя** выставить `contour_complete=true`, `master_color_boundaries_checked=true`, `approved=true`; выполнить `python scripts/locked_region_pipeline.py audit --folder NewOutput`. `READY_FOR_COLOR` выдаёт `region_review_sha256`, который вручную переносится в `color_plan.json`. Автоматически обнаружить отсутствующую белую грудку алгоритм не способен.
5. Пользователь утверждает назначения `ID → #RRGGBB` для **каждой** зоны. Идентичные HEX образуют общую группу; нужно 12–45 разных RGB. Только после согласования цвета выставить `approved=true`. Не совпадает SHA мастера, карты регионов или художественного ревью — `BLOCKED`. Не подтверждать палитру автоматически.
6. `python scripts/locked_region_pipeline.py build --folder NewOutput` раскрашивает сохранённые области **программно**, без генерации новой картинки: `Game/Zones/Zone_XXX.png`, `Game/outlines.png`, плоское превью, SVG, QA, один ZIP. Затем `verify_flat.py` и `Tools/LevelCreation/check_flat_source.py` для Unity. Превью должно собираться из PNG и отдельного слоя линий.
7. Если уровень импортируется через существующий `Import-NewLevel.ps1`, используйте готовые PNG, а не запускайте новый художественный генератор. Его собственный Unity-манифест отличается от исходного `Game/level_manifest.json` плагина; совместимость проверяйте отдельно. Unity/Play/Android — `NOT_RUN` до реальных испытаний.

Скрипт выделяет 4-связные области и фиксирует их идентификаторы и хеши. Он не может самостоятельно доказать художественную замкнутость неполных линий; граница изображения служит внешней границей зон, касающихся края. Машинный PASS не равен утверждённой художественной картинке.

**Только для новых изображений/уровней:** источник геометрии — утверждённый чёрно-белый контур, цветная версия должна иметь **строго один RGB в каждой замкнутой области**. Тени и воздушная перспектива создаются отдельными областями, а не градиентом. Базовая цель 20–45 цветов, простая сложность 12–19; экспортное полотно **1254×1254 RGBA**. Каждый `Zone_XXX.png` содержит **ровно один непрозрачный RGB** и **все островки** этой группы. Никаких дополнительных PaintZone на островок. Контур — отдельный `outlines.png`. PNG не обрезать, не сдвигать, внутри группы не сохранять тени/вариации RGB.

Источником художественных правил для ChatGPT служат настройки проекта и версия **0.4.0** личного плагина **Smart Coloring Pipeline**. Для новых рисунков основной путь: `scripts/locked_region_pipeline.py extract` → утверждение `region_review.json` → `audit` → привязка `region_review_sha256` и утверждение `color_plan.json` → `scripts/locked_region_pipeline.py build` → `scripts/verify_flat.py`. Старый `export_flat.py`/`contour_first_pilot.py` остаются legacy и не являются штатным способом раскрашивания. Результат нового пути — предварительно проверенные файловые ресурсы, **не** пройденный Unity/Android тест. Не путать разные форматы JSON плагина и Unity: Unity-импортер создаёт собственный `ArtSources/Level_NNN/level_manifest.json` из готовых PNG.

При штатном создании нового уровня `Import-NewLevel.ps1` для `rgb` **автоматически** запускает `Tools/LevelCreation/check_flat_source.py` на источнике, прежде чем готовить/импортировать ассеты. Проверка требует 12–45 файлов `Zone_001.png` и далее без пропусков номеров, одного непрозрачного RGB в каждом PNG, бинарной alpha масок, раздельных масок без прямого контакта разных цветов без контура, покрытия замкнутых внутренних областей и при наличии `Preview_Color.png` точного совпадения с наложенными слоями. Для повторного использования полного ZIP плагина можно подать распакованную папку с `Game/Zones`, `Game/outlines.png` и `Review/Preview_Color.png`; альтернативные/дублирующие `Zone_XXX.png` в одной входной папке не допускаются.

Ручная проверка источника без запуска Unity:

```powershell
& $py Tools/LevelCreation/check_flat_source.py --source "C:\путь\к\распакованному\комплекту"
```

Далее используйте обычную `Import-NewLevel.ps1 -Source ... -Number ... -Title ...` без дополнительного параметра: по умолчанию `rgb` импортирует **один RGB из каждого Zone PNG** как одну группу, проверка `check_level.py` затем подтверждает реальные цвета и собранное превью. Не переключать новые одноцветные материалы в `-GroupingMode layer`: существующий `layer` создаёт legacy-метаданные `type: gradient` даже для визуально плоских входных PNG.

**Legacy:** ранее созданные сцены, исходники и градиентные PNG **не мигрировать, не уплощать, не переписывать**. Исторический градиентный импорт допускается только явно: `-GroupingMode layer -GroupConfig <проверенный JSON>`; для старых RGB-наборов, которые намеренно требуют дробления нескольких RGB внутри маски, доступен явный `-LegacyRgbSplit`. Повторная замена старых уровней не включается без отдельной задачи. Прежние разделы ниже документируют такие исторические режимы и не отменяют стандарт новых иллюстраций.

**Границы PASS:** проверка источников и файлового экспорта не подтверждает художественную корректность, размер реальной сенсорной зоны, работу коллайдеров, Unity Play Mode или Android. Для них нужен отдельный результат и отметка `NOT_RUN`, если не проверяли. Новая картинка и первые Android-испытания должны проходить ручную визуальную оценку.

## Один запуск

Открыть проект в **одном** Unity Editor, дождаться компиляции и проверить Console.
Прочитать `AGENTS.md`, проверить `git status --short --branch` и несохранённые сцены.
Работать через официальный Unity CLI/MCP. Не запускать второй Editor.

Из корня проекта в PowerShell:

```powershell
.\Tools\LevelCreation\Import-NewLevel.ps1 -Source "4. домик" -Number 4 -Title "Домик"
```

Это пример следующего запуска, а не утверждение о проверенных материалах домика.
`-Source` принимает уникальную часть имени папки внутри
`C:\Users\Public\Documents\PaintByNumbers Exchange\уровни`, полный путь к папке
или путь к одному из её файлов. Несколько совпадений — ошибка, выбор не угадывается.
`-PreviousScene` по умолчанию — предыдущий номер (`Level_003_New` для четвёртого).
Для Python нужны **Pillow и numpy**; `-Python` задаёт другой интерпретатор.
По умолчанию используется Python из bundled Codex runtime, путь вычисляется от профиля пользователя.

Команда проверяет исходники, делает резервные копии затрагиваемых сцен/настроек в `Logs/LevelCreation`,
копирует оригиналы, готовит PNG, импортирует их через открытый Editor, создаёт сцену,
палитру, коллайдеры, карточку и переходы, добавляет сцену в EditorBuildSettings и выполняет статические проверки.
Play Mode и Android-сборка проверяются отдельно. Успешный статический импорт не означает готовность игры.
Явную остановку APK пользователем соблюдать; в отчёте такая проверка остаётся stopped_by_user.

## Входные материалы

Нужен один однозначный набор `outlines.png` + `Zone_*.png` в одной папке,
а также соответствующий цветной оригинал/превью. Допускается вложенная папка с набором.
Все слои должны иметь одинаковое полное полотно, прозрачный внешний участок и непрозрачный цвет внутри.
Контур может содержать фиксированные чёрные/белые детали.

По умолчанию действует режим `rgb`: для новых уровней предшествующая строгая проверка требует ровно один RGB в каждой исходной маске, поэтому один `Zone_XXX.png` образует одну игровую группу. Старое поведение `rgb`, при котором несколько плоских RGB в маске разделяются на группы, разрешено только явно через `-LegacyRgbSplit`; количество групп не ограничено 17.
Режим `layer` включается **явно**: один исходный PNG становится одной игровой группой,
независимо от числа RGB. Художественные градиенты не уплощаются.
Отсутствующие маски, неоднозначные наборы и несогласованное цветное превью требуют разбора агентом.
Инструмент отказывает и сохраняет исходники, вместо угадывания сегментации.

## Исторические градиенты и явные объединения (только legacy)

`prepare_level.py --grouping-mode layer` принимает только RGBA-маски и сохраняет
одиночные игровые PNG побайтно. Без этого флага/настройки конфигурации старое RGB-разделение
остаётся прежним, включая отказ при более 64 непрозрачных RGB в одной маске.

`--group-config` задаёт JSON: `groupingMode: "layer"`, необязательные `colors`
(путь исходного PNG → RGB кнопки), `mergeGroups`, `sourceSha256`, `approvedClosePairs`.
Готовая проверенная конфигурация: [Kot7.gradient.json](../Tools/LevelCreation/Configs/Kot7.gradient.json).
Она закрепляет SHA256 всех 18 масок «7. кот» и объединяет только Zone_017/018.
Zone_013/016 остаются разными группами; исходные имена слоёв не путать с их художественными названиями.

Представитель палитры — реальный непрозрачный RGB, ближайший к поканальной медиане.
Он влияет **только на кнопку**. Проверка близости использует CIE76, sRGB/D65, порог ΔE<6:
это кандидаты на проверку, а не доказательство дублирования. Автоматического объединения нет.
Неподтверждённая близкая пара останавливает подготовку до записи файлов.
`approvedClosePairs` — явное разрешение оставить пару раздельной; каждый элемент содержит
`sources: ["Zone_001.png", "Zone_002.png"]` и `colors: [[r,g,b], [r,g,b]]`.
Разрешение привязано к точным RGB; устаревшие разрешения и неизвестные слои отклоняются.
Для «7. кот» после согласованного объединения 17/18 неподтверждённых близких пар нет.

`mergeGroups: [["Zone_017.png", "Zone_018.png"]]` создаёт одну игровую группу/PNG/кнопку
из нескольких источников. Разрешены только последовательные исходные слои без **любого**
пересечения ненулевой alpha. Объединение копирует исходные RGBA всех видимых пикселей,
не смешивает и не перекрашивает их. Все исходные PNG остаются в Original побайтно;
каждый исходник перечисляется в `groups[].sources` с файловым и пиксельным SHA256.
Два совпадающих по цвету объекта с разными градиентами автоматически не сливаются.

В манифесте schema=1 добавлены `groupingMode` и `groups[].type` (`flat`/`gradient`).
Градиентная группа содержит `paletteMethod`, `rgbaSha256`, `sources`, `mergeMethod`;
`color` по-прежнему задаёт кнопку, а не tint спрайта. Старый манифест без новых полей
читается как `rgb`/`flat`. Смена режима, палитры или идентичности существующего результата
требует миграции и отклоняется; старые игровые сцены не пересоздаются.

Безопасная файловая проверка (не создаёт сцен и ассетов):

```powershell
& $py Tools/LevelCreation/prepare_level.py --source "7. кот" `
  --output Assets/_Project/Art/Levels/Gradient_Kot7_DryRun `
  --scene Gradient_Kot7_DryRun_004 --title "Кот 7" `
  --group-config Tools/LevelCreation/Configs/Kot7.gradient.json --validate-only
```

Для фактической подготовки вне проекта запускать из отдельной временной рабочей папки
с абсолютными путями к скрипту/конфигурации и относительным output; это создаёт файлы только
в этой папке. Рабочую сцену не импортировать без отдельного разрешения.
Import-NewLevel принимает `-GroupingMode layer -GroupConfig <путь>`.
С разрешения пользователя Level_004_New заменён на «7. кот» через `-ReplaceExisting`:

```powershell
.\Tools\LevelCreation\Import-NewLevel.ps1 -Source "7. кот" -Number 4 -Title "Кот 7" `
  -GroupingMode layer -GroupConfig Tools/LevelCreation/Configs/Kot7.gradient.json -ReplaceExisting
```

Замена требует существующих сцены/манифеста и чистого состояния открытых сцен.
Комплект сначала готовится и проверяется в Logs/staging; набор путей PNG должен совпасть с активным.
Резервируются старая сцена с .meta, ресурсы, архив, меню, предыдущая сцена и Build Settings.
PNG заменяются на прежних путях, .meta/GUID сохраняются. Старый архив остаётся в Logs/backup.
`LevelCreationTools.Create(..., true)` переиспользует четвёртую сцену и карточку; прежние уровни
и настройки сборки не сохраняются повторно, если связи уже верны. Без флага готовая сцена только проверяется.
Перед Play-тестами отдельно резервировать PlayerPrefs; после замены сбрасывать только несовместимый
прогресс целевого уровня, после тестов восстанавливать пользовательские сохранения.

Проверка других основных папок новым `layer --validate-only` (без изменения файлов):
«Мандала» проходит — 12 групп, 284 участка после распределения общих alpha-границ;
«Домик» всё ещё имеет 1978 непрозрачных пересечений; «Медуза» требует однозначного
`outlines.png` вместо альтернативного имени; «Чаепитие» — 157 пересечений и 2 пробела;
«Поезд» — 1281 пересечение и 2 пробела. Поддержка градиентов не исправляет эти дефекты.
Для каждого рисунка выбор «слой = игровая группа» и объединения должны быть явными;
конфигурацию «Кот 7» с закреплёнными хешами нельзя переносить на другой рисунок.

## Структура

```text
ArtSources/Level_NNN/
  Original/                 неизменённые графические исходники, включая .ai
  Working/geometry.json     контуры коллайдеров и контрольные точки
  Working/hitmask.bytes     uint16 LE карта ID, используется только проверками
  level_manifest.json       имя, полотно, игровые группы/источники, палитра, SHA256, проверки
Assets/_Project/Art/Levels/Level_NNN/
  Outline/outlines.png
  Zones/Zone_001.png ...
  Previews/Preview_Color.png
  Previews/Preview_BW.png
Assets/_Project/Scenes/Level_NNN_New.unity
```

`Other/` создаётся только при необходимости дополнительных игровых изображений.
Старые Level_001/002 сохраняют свою существующую плоскую структуру.
Промежуточные маски, отчёты и скриншоты не хранить в Assets.

## Стабильные правила реализации

- PNG **никогда не обрезаются и не масштабируются**; центр и размеры сохраняются.
- Sprite: Single, Full Rect, pivot `(0.5, 0.5)`, 100 PPU, NPOT None, Alpha From Input,
  Alpha Is Transparency, Clamp, Bilinear, без mipmaps. Android RGBA32 без потерь.
- Цвет хранится в PNG. SpriteRenderer.tint всегда белый; кнопка получает RGB группы
  (для градиента — отдельный представительный RGB, исходные пиксели не меняются).
- Один `PaintZone` на цвет, в спрайте могут быть десятки раздельных участков.
  Это сохраняет текущую механику «нажатие закрашивает всю цветовую группу».
  Не создавать отдельные PaintZone с одним ID для каждого участка: PaintController считает цвет завершённым целиком.
- PolygonCollider2D строится по alpha>=128: внешние контуры и отверстия имеют противоположное направление.
  Допуск упрощения 0.45 пикселя; общие сглаженные границы принадлежат одному коллайдеру.
- Камера использует прежние GameplayViewport и отдельный фон; бумага подгоняется в новой сцене.
- Новая сцена завершается переходом в MainMenu, предыдущая получает её имя в nextLevelSceneName.
- Карточка копируется из последней существующей; сетка меню и WinPanel не переделываются.
  Новая сцена включается в сборку, добавляется в список сброса MainMenuController.
- Progress хранится по имени сцены и colorId. Числовые TMP-подписи явно выключаются
  в Awake через PaintZone.DisableZoneLabels и SelectColor.DisablePaletteLabels. Это не ошибка импорта;
  изменение этого поведения требует отдельного согласования.

## Повторный запуск и изменения

Существующие оригиналы/PNG сравниваются побайтно. Равные пропускаются; отличающиеся не перезаписываются.
Манифест проверяет неизменность имени сцены, полотна, ID и хешей спрайтов.
Повторный запуск существующую сцену **проверяет**, не пересоздаёт.
Для осознанного обновления изображения, палитры или состава групп нужен отдельный проверенный план миграции;
не удалять `.meta`. Перемещения уже импортированных ресурсов — только AssetDatabase.MoveAsset.
Оригиналы из Exchange не удаляются.

Промежуточный полный отчёт создаётся только с -GenerateReport; receipt создаётся всегда. -VerboseOutput раскрывает полный вывод явно. Это не Play Mode PASS.

`LevelCreationBatch.RunReadOnly(requestFile)` проверяет указанные манифесты/все region samples в native PolygonCollider2D на временной preview scene, закрывает её и проверяет неизменность открытых сцен. ## Точечная защита геометрии от native sliver triangles

`geometryMaxEdgePixels: {"Zone_009.png": 32}` — необязательная настройка layer-конфига только для явно указанного источника. `geometry_paths` добавляет коллинеарные вершины на длинные отрезки, сохраняя их точную границу, winding, отверстия и все островки. Без настройки возвращается прежний список контуров без изменений. Проверка check_level учитывает ту же явную политику. Настройка не меняет PNG, палитру, colorId, runtime и существующие сцены.

Основание: у подготовленного Домика группа9, точка(654,0), исходный native mesh имел тонкую щель между sliver triangles около0.003пикселя. До внешнего контура0.5пикселя. Параметр Delaunay не устранял пропуск. Коллинеарное разбиение рёбер до32px устраняет его без сдвига контура и без удаления маленьких фрагментов. Политику не включать глобально; готовые уровни1–4 не пересоздавать.

Проверки: `test_geometry_policy.py` и прежний `test_preparation.py`; после подготовки обязательны независимая растеризация и native-проверка, включая спорную точку и островки всех групп. Белые неподвижные художественные детали допустимы в outlines.png и не создают игровую группу.


`geometryRectangles: ["Zone_004.png"]` — вторая точечная политика для подтверждённых native-пропусков: покрытие всех центров пикселей исходной alpha>=128 области прямоугольниками из горизонтальных runs. Соседние одинаковые runs объединяются по вертикали. Отверстия, островки и все пиксели сохранены; PNG и число игровых групп не меняются. Политика выключена по умолчанию. Каждый прямоугольник имеет только устойчивые прямые углы. Обязательна полная native-проверка всех пикселей после генерации.

Native-генератор объединяет соприкасающиеся path-границы и может создавать ложные треугольники. Поэтому прямоугольники отделены зазором0.02px: каждая сторона сдвинута внутрь на0.01px. Это только геометрия, не RGB/alpha PNG; все центры пикселей сохранены. Между соседними прямоугольниками есть субпиксельные зазоры, поэтому такую политику применять только явно и проверять native-попадания всех пикселей; точное непрерывное покрытие границы не заявляется.


## Импорт готового PASS-комплекта без повторной подготовки PNG

Файлы готового комплекта вне проекта не изменяются.

Editor-инструмент сохраняет неизменные настройки импорта и идентичные пути PolygonCollider2D. При изменении путей collider временно отключается до завершения SetPath.
