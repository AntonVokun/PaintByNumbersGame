# Создание уровней «Умной раскраски»

Рабочие образцы: `Level_003_New` («Котик на круге») и градиентный `Level_004_New` («7. кот»), Unity 6000.4.4f1.
Технический шаблон: `Assets/_Project/Scenes/Level_002_New.unity`.
Конвейер не меняет runtime-скрипты, WinPanel и старую графику.

## Один запуск

Открыть проект в **одном** Unity Editor, дождаться компиляции и проверить Console.
Прочитать `AGENTS.md`, проверить `git status --short --branch` и несохранённые сцены.
Работать через официальный Unity CLI/MCP. Не запускать второй Editor.

Из корня проекта в PowerShell:

```powershell
.\Tools\LevelCreation\Import-NewLevel.ps1 -Source "4. домик" -Number 4 -Title "Домик"
```

Это пример следующего запуска, а не утверждение о проверенных материалах домика.
`-Source` принимает уникальную часть имени папки внутри
`C:\Users\Public\Documents\PaintByNumbers Exchange\уровни`, полный путь к папке
или путь к одному из её файлов. Несколько совпадений — ошибка, выбор не угадывается.
`-PreviousScene` по умолчанию — предыдущий номер (`Level_003_New` для четвёртого).
Для Python нужны **Pillow и numpy**; `-Python` задаёт другой интерпретатор.
По умолчанию используется Python из bundled Codex runtime, путь вычисляется от профиля пользователя.

Команда проверяет исходники, делает резервные копии затрагиваемых сцен/настроек в `Logs/LevelCreation`,
копирует оригиналы, готовит PNG, импортирует их через открытый Editor, создаёт сцену,
палитру, коллайдеры, карточку и переходы, добавляет сцену в EditorBuildSettings и выполняет статические проверки.
Play Mode и Android-сборка проверяются отдельно. Успешный статический импорт не означает готовность игры.
Явную остановку APK пользователем соблюдать; в отчёте такая проверка остаётся stopped_by_user.

## Входные материалы

Нужен один однозначный набор `outlines.png` + `Zone_*.png` в одной папке,
а также соответствующий цветной оригинал/превью. Допускается вложенная папка с набором.
Все слои должны иметь одинаковое полное полотно, прозрачный внешний участок и непрозрачный цвет внутри.
Контур может содержать фиксированные чёрные/белые детали.

По умолчанию действует режим `rgb`: несколько непрозрачных плоских RGB в одной маске
автоматически разделяются на группы; число групп не фиксировано и не ограничено 17.
Режим `layer` включается **явно**: один исходный PNG становится одной игровой группой,
независимо от числа RGB. Художественные градиенты не уплощаются.
Отсутствующие маски, неоднозначные наборы и несогласованное цветное превью требуют разбора агентом.
Инструмент отказывает и сохраняет исходники, вместо угадывания сегментации.

## Градиенты и явные объединения

`prepare_level.py --grouping-mode layer` принимает только RGBA-маски и сохраняет
одиночные игровые PNG побайтно. Без этого флага/настройки конфигурации старое RGB-разделение
остаётся прежним, включая отказ при более 64 непрозрачных RGB в одной маске.

`--group-config` задаёт JSON: `groupingMode: "layer"`, необязательные `colors`
(путь исходного PNG → RGB кнопки), `mergeGroups`, `sourceSha256`, `approvedClosePairs`.
Готовая проверенная конфигурация: [Kot7.gradient.json](../Tools/LevelCreation/Configs/Kot7.gradient.json).
Она закрепляет SHA256 всех 18 масок «7. кот» и объединяет только Zone_017/018.
Zone_013/016 остаются разными группами; исходные имена слоёв не путать с их художественными названиями.

Представитель палитры — реальный непрозрачный RGB, ближайший к поканальной медиане.
Он влияет **только на кнопку**. Проверка близости использует CIE76, sRGB/D65, порог ΔE<6:
это кандидаты на проверку, а не доказательство дублирования. Автоматического объединения нет.
Неподтверждённая близкая пара останавливает подготовку до записи файлов.
`approvedClosePairs` — явное разрешение оставить пару раздельной; каждый элемент содержит
`sources: ["Zone_001.png", "Zone_002.png"]` и `colors: [[r,g,b], [r,g,b]]`.
Разрешение привязано к точным RGB; устаревшие разрешения и неизвестные слои отклоняются.
Для «7. кот» после согласованного объединения 17/18 неподтверждённых близких пар нет.

`mergeGroups: [["Zone_017.png", "Zone_018.png"]]` создаёт одну игровую группу/PNG/кнопку
из нескольких источников. Разрешены только последовательные исходные слои без **любого**
пересечения ненулевой alpha. Объединение копирует исходные RGBA всех видимых пикселей,
не смешивает и не перекрашивает их. Все исходные PNG остаются в Original побайтно;
каждый исходник перечисляется в `groups[].sources` с файловым и пиксельным SHA256.
Два совпадающих по цвету объекта с разными градиентами автоматически не сливаются.

В манифесте schema=1 добавлены `groupingMode` и `groups[].type` (`flat`/`gradient`).
Градиентная группа содержит `paletteMethod`, `rgbaSha256`, `sources`, `mergeMethod`;
`color` по-прежнему задаёт кнопку, а не tint спрайта. Старый манифест без новых полей
читается как `rgb`/`flat`. Смена режима, палитры или идентичности существующего результата
требует миграции и отклоняется; старые игровые сцены не пересоздаются.

Безопасная файловая проверка (не создаёт сцен и ассетов):

```powershell
& $py Tools/LevelCreation/prepare_level.py --source "7. кот" `
  --output Assets/_Project/Art/Levels/Gradient_Kot7_DryRun `
  --scene Gradient_Kot7_DryRun_004 --title "Кот 7" `
  --group-config Tools/LevelCreation/Configs/Kot7.gradient.json --validate-only
```

Для фактической подготовки вне проекта запускать из отдельной временной рабочей папки
с абсолютными путями к скрипту/конфигурации и относительным output; это создаёт файлы только
в этой папке. Рабочую сцену не импортировать без отдельного разрешения.
Import-NewLevel принимает `-GroupingMode layer -GroupConfig <путь>`.
С разрешения пользователя Level_004_New заменён на «7. кот» через `-ReplaceExisting`:

```powershell
.\Tools\LevelCreation\Import-NewLevel.ps1 -Source "7. кот" -Number 4 -Title "Кот 7" `
  -GroupingMode layer -GroupConfig Tools/LevelCreation/Configs/Kot7.gradient.json -ReplaceExisting
```

Замена требует существующих сцены/манифеста и чистого состояния открытых сцен.
Комплект сначала готовится и проверяется в Logs/staging; набор путей PNG должен совпасть с активным.
Резервируются старая сцена с .meta, ресурсы, архив, меню, предыдущая сцена и Build Settings.
PNG заменяются на прежних путях, .meta/GUID сохраняются. Старый архив остаётся в Logs/backup.
`LevelCreationTools.Create(..., true)` переиспользует четвёртую сцену и карточку; прежние уровни
и настройки сборки не сохраняются повторно, если связи уже верны. Без флага готовая сцена только проверяется.
Перед Play-тестами отдельно резервировать PlayerPrefs; после замены сбрасывать только несовместимый
прогресс целевого уровня, после тестов восстанавливать пользовательские сохранения.

Проверка других основных папок новым `layer --validate-only` (без изменения файлов):
«Мандала» проходит — 12 групп, 284 участка после распределения общих alpha-границ;
«Домик» всё ещё имеет 1978 непрозрачных пересечений; «Медуза» требует однозначного
`outlines.png` вместо альтернативного имени; «Чаепитие» — 157 пересечений и 2 пробела;
«Поезд» — 1281 пересечение и 2 пробела. Поддержка градиентов не исправляет эти дефекты.
Для каждого рисунка выбор «слой = игровая группа» и объединения должны быть явными;
конфигурацию «Кот 7» с закреплёнными хешами нельзя переносить на другой рисунок.

## Структура

```text
ArtSources/Level_NNN/
  Original/                 неизменённые графические исходники, включая .ai
  Working/geometry.json     контуры коллайдеров и контрольные точки
  Working/hitmask.bytes     uint16 LE карта ID, используется только проверками
  level_manifest.json       имя, полотно, игровые группы/источники, палитра, SHA256, проверки
Assets/_Project/Art/Levels/Level_NNN/
  Outline/outlines.png
  Zones/Zone_001.png ...
  Previews/Preview_Color.png
  Previews/Preview_BW.png
Assets/_Project/Scenes/Level_NNN_New.unity
```

`Other/` создаётся только при необходимости дополнительных игровых изображений.
Старые Level_001/002 сохраняют свою существующую плоскую структуру.
Промежуточные маски, отчёты и скриншоты не хранить в Assets.

## Стабильные правила реализации

- PNG **никогда не обрезаются и не масштабируются**; центр и размеры сохраняются.
- Sprite: Single, Full Rect, pivot `(0.5, 0.5)`, 100 PPU, NPOT None, Alpha From Input,
  Alpha Is Transparency, Clamp, Bilinear, без mipmaps. Android RGBA32 без потерь.
- Цвет хранится в PNG. SpriteRenderer.tint всегда белый; кнопка получает RGB группы
  (для градиента — отдельный представительный RGB, исходные пиксели не меняются).
- Один `PaintZone` на цвет, в спрайте могут быть десятки раздельных участков.
  Это сохраняет текущую механику «нажатие закрашивает всю цветовую группу».
  Не создавать отдельные PaintZone с одним ID для каждого участка: PaintController считает цвет завершённым целиком.
- PolygonCollider2D строится по alpha>=128: внешние контуры и отверстия имеют противоположное направление.
  Допуск упрощения 0.45 пикселя; общие сглаженные границы принадлежат одному коллайдеру.
- Камера использует прежние GameplayViewport и отдельный фон; бумага подгоняется в новой сцене.
- Новая сцена завершается переходом в MainMenu, предыдущая получает её имя в nextLevelSceneName.
- Карточка копируется из последней существующей; сетка меню и WinPanel не переделываются.
  Новая сцена включается в сборку, добавляется в список сброса MainMenuController.
- Progress хранится по имени сцены и colorId. Числовые TMP-подписи явно выключаются
  в Awake через PaintZone.DisableZoneLabels и SelectColor.DisablePaletteLabels. Это не ошибка импорта;
  изменение этого поведения требует отдельного согласования.

## Повторный запуск и изменения

Существующие оригиналы/PNG сравниваются побайтно. Равные пропускаются; отличающиеся не перезаписываются.
Манифест проверяет неизменность имени сцены, полотна, ID и хешей спрайтов.
Повторный запуск существующую сцену **проверяет**, не пересоздаёт.
Для осознанного обновления изображения, палитры или состава групп нужен отдельный проверенный план миграции;
не удалять `.meta`. Перемещения уже импортированных ресурсов — только AssetDatabase.MoveAsset.
Оригиналы из Exchange не удаляются.

## Проверки и отдельные команды

```powershell
# $py — выбранный Python с Pillow и numpy
& $py Tools/LevelCreation/check_level.py ArtSources/Level_003/level_manifest.json
& $py Tools/LevelCreation/test_preparation.py
```

Через MCP eval или `unity command eval --caller plugin --skill unity-cli`:

```csharp
LevelCreationTools.Validate("Assets/_Project/Art/Levels/Level_003");
LevelCreationTools.ValidateIntegration("Assets/_Project/Art/Levels/Level_003", "Level_002_New");
LevelCreationTools.ValidatePixels("Assets/_Project/Art/Levels/Level_003", 4);
```

Перед Validate активной должна быть новая сцена. ValidateIntegration открывает меню,
предыдущую и новую сцену; не использовать при несохранённых изменениях.
Плотная проверка — сетка с шагом 4 пикселя, плюс отдельная точка каждого связного участка.
Точки ровно на внутренних рёбрах физической триангуляции проверяются с симметричным допуском
менее 0.002 пикселя: это учитывает точность native OverlapPoint, не раздувает геометрию.

Перед Play тестом сохранить прогресс через
`LevelCreationVerification.BackupProgress("Logs/LevelCreation/unique-session/playerprefs.json")`.
После теста выйти из Play и вызвать `RestoreProgress` с **тем же** путём, затем сверить ключи.
Для автоматического ввода есть QueuePointer, ButtonPoint, ZonePoint и AutoPaint;
это события Input System, а не ручное присвоение painted=true. RemoveTestInput убирает
синтетическую мышь и восстанавливает временные настройки фокуса.
Отдельно сохранять/возвращать PlayerSettings.runInBackground при изменении для теста.

Android собирать через подключённый Editor из всех включённых сцен.
Для headless сначала закрыть Editor. Не обновлять Unity/UPM ради создания контента.

## Граница автоматизации

Полностью автоматизированы поиск однозначной папки, архивирование, подготовка готовых масок,
раскладка, импорт, генерация сцены/палитры/коллайдеров, меню, переходы, Build Settings и статические проверки.
Unity-агент запускает Play-тесты, оценивает скриншоты и проверяет Console/сборку.
На устройстве остаются проверка ощущений от touch, звука, производительности и разных экранов.
Файловая переносимость проверена на «7. кот»: 18 исходных масок → 17 групп после явного
объединения 17/18, 73 участка, 81 контур; сохранены пиксели и полный составленный рисунок.
Повторная подготовка не меняет хеши. PNG/геометрия/hitmask прежнего «Котика на шине»
побайтно совпадают с результатом до доработки. Это не новый Play Mode или импорт сцены.
Геометрия дополнительно проверена независимой растеризацией; native PolygonCollider2D
и игровые взаимодействия «7. кот» остаются NOT_RUN до разрешённого создания тестового уровня.

## Отчёт и карта

После успешного статического импорта команда сохраняет краткую квитанцию в `AgentSync/level-imports/`
и вызывает генератор отчёта. Сцена, меню, сброс, Build Settings, размер, цвета, островки и ресурсы
считываются из фактических сцен/манифеста. Квитанция статического импорта не подтверждает Play Mode.
Агент добавляет результаты игровых проверок в observations.json, обновляет SCENE_MAP и повторно
формирует/публикует итог по [AGENT_SYNC_GUIDE](AGENT_SYNC_GUIDE.md).
Контрольный список — [LEVEL_CREATION_CHECKLIST](../LEVEL_CREATION_CHECKLIST.md),
короткое задание для Medium — [LEVEL_CREATION_PROMPT](../LEVEL_CREATION_PROMPT.md).
